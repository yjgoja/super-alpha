## 🔴 미수정 — 높음 (실계좌 손실 직결)

### A. 주문 이중 발행 3계층 (물량 괴리의 근본 원인)
같은 가정이 세 층에 박혀 있다: **"주문 실패 = 주문 미도달"**. 검증된 적 없다.

| 계층 | 위치 | 실패 시 동작 |
|---|---|---|
| HTTP | `src/lib/metaapi.ts` `api()` catch | 네트워크 오류 → 동일 POST `/trade` 재전송 (멱등키 없음) |
| 전송 | `src/lib/metaapi.ts` `placeMarketOrder` | 스트림 타임아웃 → REST로 재발행 (credit/stops 오류만 조기 반환) |
| 전략 | `meta-engine.ts` 나체 재시도 4곳 | 실패 사유 무관하게 재발행 |

**수정 방향:** 재발행 전 반드시 브로커 물량을 조회해 실제 체결 여부를 확인.
`POST /trade` 는 네트워크 오류 시 재시도 금지(fail-closed) 후 확인 경로로.

### B. 락 공백 / 고아 락
- Vercel cron `maxDuration=60` 강제 종료 시 `finally` 미실행 → 락이 최대 180초 고아
  → 그동안 Render 엔진이 해당 계좌를 틱하지 못함 (TP/SL 관리 공백)
- SIGTERM(배포) 시 보유 락 미해제 → 배포마다 최대 3분 공백
- 틱 중 락 갱신(하트비트) 없음 + 틱 소요 상한 없음 → 180초 초과 시 탈취 가능
- `scripts/_clear-tick-lock.ts` 가 `where` 없이 전체 락 삭제 (CLAUDE.md 가 금지한 코드)

### C. 스냅샷 신선도 미검증
- `metaapi.ts fetchSnapshot` 이 `allowStaleMs` 판정 **전에** 스트림값을 반환 →
  `allowStaleMs: 0` 요청(주문 확인·게이트)이 무력화
- `metaapi-stream.ts readStreamSnapshot` 이 `conn.synchronized` 미검사,
  `ready` 플래그를 재검증하지 않음, terminalState 갱신 시각 미확인

### D. 금액 계산
- DCA 직전 `projLive` 가 **DCA 이전** `brokerMarginSum` 을 씀 → 새 주문에 붙는 TP/SL이
  실제보다 좁게 계산됨 (`meta-engine.ts` 표 로직 경로). 일반 경로는 `null` 을 넘김 — 두 경로 불일치
- `brokerMarginSum` 이 일부 포지션의 `margin` 누락 시 **부분합**을 전체로 신뢰 → ROI 분모 과소 → 조기 손절
- `levelLots()` 가 L0 는 `SymbolBot.startLots`, L1+ 는 계좌 오버라이드 표를 씀 →
  둘이 다르면 **L1 이 L0 보다 작아지는 역마틴게일** 발생 가능
  ⚠️ 사다리 의미를 바꾸는 수정이므로 사람 확인 필요

### E. 원자성
- `filledLevel` 을 트랜잭션 밖에서 read-modify-write (`{increment:1}` 미사용)
- 바스켓 `status: "closed"` 전이에 CAS 없음 → 이중 청산·이중 재진입·카운터 중복
- `basketLeg` / `Fill` / `filledLevel` 3-write 가 비원자적 → 중간 실패 시 DCA 영구 정체
- `Basket` 에 `(accountId, symbol, direction, status)` 유니크 없음,
  `BasketLeg` 에 `(basketId, level)` 유니크 없음 → 최후 방어선 부재

## 🟡 미수정 — 중간

- 모든 429를 "6시간 크레딧 소진"으로 취급 → 일시적 429 하나로 **전 계좌 청산이 15분 정지**
  (`isTradeCreditExhausted` 의 두 번째 정규식이 소프트 재시도 경로를 죽은 코드로 만듦)
- DCA 직전 `syncBrokerBasketProtection` 반환값 무시 (fail-open) → 레그별 TP 불일치 → 부분 청산 잔여
- SL 클램프가 `null` 을 만들면 "보호됨"으로 집계 (`allProtected: true`)
- rate limit 이 `X-Forwarded-For` 좌측 값 신뢰 → 스푸핑으로 우회 가능 (로그인 브루트포스)
- `skipEntryIfMarginInsufficient` 가 `liveState` 신선도 미검사 + `budget<=0` 이면 통과 (fail-open)
- 비USD 호가 종목(USDJPY/GBPJPY)이 API로 등록되면 PnL·마진이 통화 환산 없이 계산됨 (현재 UI 옵션엔 없음 — 잠재)
- 알 수 없는 심볼의 contract size 가 100,000 으로 조용히 폴백. `getSymbolTradeSpec` 이 브로커 실제값을 안 가져옴

## 🟢 확인 결과 문제 없음

- 인증·권한: 모든 계좌 변경 경로가 `userId` 로 스코프됨. 교차 사용자 접근 없음
- 입력 검증: zod 로 롯·회차·금액 상한 강제. 음수/NaN/초대형 값 유입 경로 없음

- 사다리 롯 반올림 누적 오차: 없음 (레벨마다 base×mult^i 로 독립 계산)
