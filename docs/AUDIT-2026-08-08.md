### B. 락 공백 / 고아 락 — ✅ 수정 완료 (커밋 8ea43a8)
- 틱 중 락 갱신(하트비트) 추가 — `startTickLockRenewal`, 임계의 1/3 주기,
  "내가 심은 값일 때만" 갱신하므로 뺏긴 락을 되찾지 않는다
- 종료 시 락 반납 — `releaseAllTickLocks` + tick-direct SIGTERM 핸들러(3초 상한)
- `TICK_LOCK_STALE_MS` 180초 → 90초 (갱신이 있으니 안전, 고아 락 공백 절반)
- `_clear-tick-lock.ts` 가 stale 만 정리하도록 수정 (살아있는 락 보호)
- `/api/cron/tick` 이 `undeployIdleAccounts` 경과를 예산에 반영 (60초 초과 → 강제종료 → 고아 락 방지)

### C. 스냅샷 신선도 — 🟡 부분 수정 (커밋 진행중)
- ✅ `readStreamSnapshot` 이 `connectedToBroker` 를 **필수**로 요구하도록 수정.
  예전 조건 `!connectedToBroker && !connected` 는 둘 다 거짓일 때만 막아서,
  MT5 가 브로커 연결을 잃어도 `connected=true` 면 낡은 포지션을 내줬다
- ✅ `conn.synchronized` 검사 추가 (타입에 선언만 되고 아무도 안 읽던 필드)
- ⬜ `fetchSnapshot` 이 `allowStaleMs` 판정 전에 스트림값을 반환하는 구조는 그대로.
  다만 위 두 검사로 "연결이 끊긴 채 낡은 값" 은 걸러진다. 남은 위험은
  "플래그는 정상인데 terminalState 갱신만 멈춘" 경우 —
  `confirmLiveVolumeIncreased` 에서는 증가를 못 봐서 **실패(안전)** 쪽으로 떨어지고,
  주문 재발행도 이제 막혀 있어 피해가 제한된다. 완전 해결하려면 terminalState
  갱신 시각을 추적해야 하는데, 매 확인마다 REST 를 쓰면 크레딧을 태운다

### E. 원자성 — ✅ 수정 완료

### D. 금액 계산

- `brokerMarginSum` 이 일부 포지션의 `margin` 누락 시 **부분합**을 전체로 신뢰 → ROI 분모 과소 → 조기 손절

  → **수정 안 함으로 결정 (2026-08-08).** 활성 봇 25개 전부 오버라이드가 없어

## 🟡 미수정 — 중간

- 모든 429를 "6시간 크레딧 소진"으로 취급 → 일시적 429 하나로 **전 계좌 청산이 15분 정지**
  (`isTradeCreditExhausted` 의 두 번째 정규식이 소프트 재시도 경로를 죽은 코드로 만듦)
- DCA 직전 `syncBrokerBasketProtection` 반환값 무시 (fail-open) → 레그별 TP 불일치 → 부분 청산 잔여
- SL 클램프가 `null` 을 만들면 "보호됨"으로 집계 (`allProtected: true`)
- rate limit 이 `X-Forwarded-For` 좌측 값 신뢰 → 스푸핑으로 우회 가능 (로그인 브루트포스)
- `skipEntryIfMarginInsufficient` 가 `liveState` 신선도 미검사 + `budget<=0` 이면 통과 (fail-open)
- 비USD 호가 종목(USDJPY/GBPJPY)이 API로 등록되면 PnL·마진이 통화 환산 없이 계산됨 (현재 UI 옵션엔 없음 — 잠재)
- 알 수 없는 심볼의 contract size 가 100,000 으로 조용히 폴백. `getSymbolTradeSpec` 이 브로커 실제값을 안 가져옴

## 🟢 확인 결과 문제 없음

- 입력 검증: zod 로 롯·회차·금액 상한 강제. 음수/NaN/초대형 값 유입 경로 없음

- 사다리 롯 반올림 누적 오차: 없음 (레벨마다 base×mult^i 로 독립 계산)
